① Agentic Loop — Pipeline as Recurring Cycle

Each ingest request drives one full loop. The orchestrator coordinates all stages; the HTTP endpoint holds the single db.commit() boundary. Failed runs re-enter at the same entry point on retry.

parsers (I/O)
heuristics (regex, locked)
LLM (Bedrock Nova Lite)
validator (coerce + merge)
persister (atomic savepoint)
logger (flush, unconditional)

② Full Stack Architecture — Ex1 → Ex2 → Ex3

Three tiers, one swap seam. The frontend (lib/db.ts) never changed beyond its function bodies. The pipeline module was added in Ex3 without touching any prior layer.

③ Structured Extraction Flow — Heuristics + LLM → Reliable Summary

The pipeline combines deterministic regex and probabilistic LLM via a trust hierarchy. Regex locks in structured fields first. The LLM fills semantic gaps. The validator resolves all conflicts and coerces types — collecting every warning before emitting a result.

④ Error & Failure Paths — Nonsense → Trusted Result

Every failure mode is a named type with deterministic handling. No silent swallowing. ParseErrors never touch the DB. BedrockErrors and ValidationErrors always produce an extraction_runs row. The three-outcome type system makes incorrect handling structurally impossible.

FAILED
No entity created. Safe to retry. Caused by: bad JSON, missing full_name, unreadable file, Bedrock error. extraction_runs row logged with errors[].
entity_id=NULL · HTTP 422
PARTIAL
Entity created but has holes. Some fields coerced (string→int + warning). Usable for search but check warnings before assigning to position.
Ex6 agent → human review queue
SUCCESS
All required fields present and typed. Hints applied. warnings=[]. Candidate persisted atomically (parent + all 5 child tables in one savepoint).
entity_id=cv_XXXXXXXX · HTTP 201
