CV Ingestion Pipeline

From HTTP file upload to structured candidate record — six extraction and persistence stages, showing which rely on heuristics, which on LLM inference, and where validation enforces the trust hierarchy.

Stage Types & Color Coding

Parse (code) — deterministic. Extracts raw text from binary. Fails fast with a structured error if format is unrecognised.
Heuristics (regex) — deterministic. Matched values guaranteed correct. High precision, low recall — only fires on recognisable patterns.
LLM (Nova Lite) — probabilistic. Extracts all structured fields. Informed by heuristic hints but not bound by them. May hallucinate.
Validation (code) — strips fences, parses JSON, coerces types. Hint override is the real enforcement: heuristic values win unconditionally.
Observability — always written, including on FAILED. Stores full prompt + raw LLM output for retrospective analysis in DBeaver.
Persistence (SAVEPOINT) — all 6 candidate tables succeed or all roll back. Single outer db.commit() at the endpoint — no partial state reaches Postgres.

The heuristic / LLM split is deliberate: regexes are high-precision but low-recall (they only fire on recognisable contact-line patterns); the LLM covers every remaining field but may produce inconsistent output. Validation is the arbiter — it applies heuristic values last, unconditionally, so the system gets guaranteed accuracy where the regex fires and best-effort inference everywhere else. ParseError and BedrockError exit before any DB write. ValidationError logs a FAILED row to extraction_runs but writes no entity — the audit trail is always complete.
