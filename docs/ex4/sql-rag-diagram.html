SQL-RAG Chat Pipeline

Natural-language question to grounded HR answer — five deterministic and LLM stages, showing the three safety layers, where history is folded in, and where observability is unconditionally written.

Color coding

HTTP entry — POST /api/chat; question + history arrive here
LLM stage — Nova Lite via BedrockClient.converse(); generator + answerer
Guard — deterministic SQL validation; no LLM, no network; pure Python
Executor — read-only Postgres transaction; bounded result set
Observability — query_runs row; written on every outcome including failure
Response + commit — ChatResponse; single db.commit() at endpoint boundary
Error paths — dashed; all three resolve to a query_runs row with error status

History is handled differently at each LLM stage: the generator folds prior turns as a compact text preamble inside the USER message; the answerer passes them as real conversation entries via converse_messages() — the multi-turn learning objective of segment 06. The observability write is unconditional: every chat turn, success or failure, produces a query_runs row — symmetric with Ex3's extraction_runs.
