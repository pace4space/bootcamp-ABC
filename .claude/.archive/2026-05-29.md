## Key Learnings

### Nova Lite disobeys "No markdown fences" non-deterministically
- Same prompt, same document, two consecutive calls → Run 1: clean JSON, Run 2: ```json fenced
- The prompt instruction "No markdown fences" has ~80-95% compliance, not 100%
- Fix: one-line pre-processor in validator.py: `re.sub(r'^```json\s*', '', raw.strip()).rstrip('`').strip()`
- This should be default in any LLM output validator — markdown fences are a near-universal LLM quirk

### Google Drive MCP can't handle large binary files
- `create_file` with `base64Content` only works for small files — 19 MB / 25 MB base64 is too large as a tool parameter
- Workaround: push to GitHub instead (under 100 MB limit, no LFS needed for 19 MB)
- For large media: browser drag-and-drop or rclone are the right tools; MCP is for documents/text

### Double-ingest is not idempotent — creates a new entity each time
- Each call to `POST /api/ingest/cv` creates a new `cv_<8hex>` ID and new rows in raw_documents + extraction_runs
- No deduplication by filename or content hash — same PDF ingested twice = two candidate records
- This is a design gap for Ex4: need either a content-hash uniqueness check or a "replace" mode

## Key Learnings (afternoon)

### Google Drive / Gmail MCP egress blocked from this machine

- IP 77.125.1.105 is the MCP egress — blocked persistently, not transient
- **Workaround pattern:** raw GitHub URLs (`/raw/master/path`) for files already in repo; htmlpreview.github.io for HTML; browser drag-and-drop for Drive; gh CLI for other GH operations

### NotebookLM skill: local library is separate from actual notebook creation
- The skill manages a local JSON registry of notebook URLs — it doesn't create notebooks in NotebookLM
- User must create notebook in NotebookLM web UI, then share URL for registration
- Once registered with `notebook_manager.py add`, future queries use it by default (`activate`)
- The skill is Q&A focused; infographics/mind-maps must be generated separately (HTML/SVG)

### htmlpreview.github.io — instant HTML rendering from public repos
- URL pattern: `https://htmlpreview.github.io/?https://github.com/OWNER/REPO/blob/BRANCH/path/file.html`
- No GitHub Pages setup needed, renders immediately, mobile-compatible
- Best workaround when Pages isn't configured and Drive MCP is blocked
