## Key Learnings

### draw.io: size the corridor before placing arrows
- Rule: n parallel arrows need n×20px of corridor minimum to stay visually distinct
- 5 arrows → 100px corridor; we started at 70px (10px tracks) and had to widen to 120px after 2 rounds
- Apply this upfront: know the arrow count → set corridor width → place tables → then wire arrows
- Saved in gen-drawio SKILL.md under "Within-cluster edge routing"

### draw.io ERD iteration is Sonnet-heavy but rounds 2-3 could be Haiku
- Each iteration was: write XML → validate → export PNG → open → user feedback
- The validate+export step (python parse + CLI export + dimension check) is mechanical
- A Haiku subagent could run validation and report back; only the XML rewrite needs Sonnet
- Not worth building a skill for unless ERDs recur (Ex5+ schema changes likely)

### Bundled submission file works better than separate artifacts
- docs/submission-ex2.md with embedded git log + paragraph + ERD reference beats three loose files
- Reviewer gets one document; git log is frozen at submission time (not a live command)
- Use this pattern for Ex3+ submissions

### Session notes are not auto-filling → fixed
- session-end.sh hook now auto-fills Commits section from git log on every Stop event
- Key Learnings still requires manual input — that's intentional (signal quality over automation)
- Reminder fires if learnings section still contains template placeholder text

### post-commit hook had wrong path → fixed
- Hook was writing to `.git/.skilllog` (via `$HOOK_DIR/../`) instead of `.claude/.skilllog`
- Root cause: hook lives at `.claude/hooks/post-commit.sh` symlinked to `.git/hooks/post-commit`
- `$(dirname "$0")` resolves to `.git/hooks/`, not the repo root
- Fix: use `git rev-parse --show-toplevel` which always returns the repo root regardless of invocation path
